## 👨‍💼 Executive Summary & Engineering Philosophy

With **5+ years of hands-on production experience**, I specialize in designing, building, and operating enterprise-scale cloud foundations on **Microsoft Azure**. My core focus is delivering **resilient, self-healing, and audit-ready infrastructure** orchestrated through **modular Terraform**, containerized with **Docker**, orchestrated on **Azure Kubernetes Service (AKS)**, and automated via **Azure DevOps and GitHub Actions CI/CD pipelines**.

I approach DevOps as a disciplined software engineering practice:
- **Infrastructure is Code:** Zero manual portal clicks. Everything is version-controlled, modularized with strict semantic versioning, and protected against state corruption and drift.

**Key Engineering Architectural Decisions:**
- **Zero-Trust Egress Routing:** All outbound internet traffic from workload spokes is forcibly redirected via UDRs to Azure Firewall Premium for SNAT, FQDN filtering, and TLS payload inspection.

- **Micro-Segmentation:** Inter-subnet Network Security Groups (NSGs) implement strict least-privilege flow control with zero cross-environment contamination.

**Production Kubernetes Engineering Standards:**
- **Zero Static Service Principal Secrets:** Workload Identity binds Kubernetes service accounts to Azure User-Assigned Managed Identities via OIDC federation, eliminating password expiration and secret leak risks.
- **Dynamic Secret Rotation via Key Vault CSI:** Secrets and TLS certificates are mounted directly into memory as tmpfs volumes with an automated 2-minute rotation polling cycle.
- **Isolated Node Planes:** System node pool is tainted with `CriticalAddonsOnly`, isolating control plane utilities from user workload crash loops or memory exhaustion.
- **eBPF Kernel-Level Security:** Cilium eBPF replaces kube-proxy for line-rate packet routing, layer-7 egress filtering, and fine-grained network policy enforcement.

## 💡 Real-World Engineering Scenarios & Problem-Solving

Real cloud environments face unexpected challenges. Here is how I solve critical production infrastructure challenges:

### 🧩 Scenario 1: Eliminating Out-of-Band Cloud Drift in Multi-Developer Environments
- **The Problem:** Developers or support teams occasionally make emergency out-of-band changes directly in the Azure Portal (e.g., tweaking an NSG rule or changing a VM SKU). When the next Terraform pipeline runs, it either overwrites the fix or fails due to unexpected state discrepancy.
- **The Solution Implemented:**
  1. Built an automated **Nightly Drift Detection Workflow** in GitHub Actions running `terraform plan -detailed-exitcode` across all production state files.
  2. If drift is detected (exit code 2), an automated incident is dispatched with the exact execution plan diff to Microsoft Teams / Slack, alerting engineers before production is impacted.
  3. Enforced strict Azure Policy assignments with `Deny` effects preventing unauthorized manual resource creation outside version-controlled deployment service principals.

### 🔑 Scenario 2: Eliminating Plaintext Credentials with Azure Workload Identity & Key Vault CSI
- **The Problem:** Microservices deployed on Kubernetes traditionally required long-lived Service Principal client secrets stored as Kubernetes secrets (base64 encoded), creating credential rotation overhead and leakage risks.
- **The Solution Implemented:**
  1. Enabled **Azure Workload Identity** with OIDC federation on the AKS cluster.
  2. Mapped Kubernetes Service Accounts to Azure User-Assigned Managed Identities with least-privilege RBAC roles.
  3. Deployed the **Azure Key Vault Secrets Store CSI Driver** to mount secrets, database connection strings, and certificates directly into pods as in-memory filesystem volumes with automated 2-minute rotation.
  4. Result: Zero plaintext secrets stored in git or Kubernetes etcd, zero manual rotation downtime.

### 🛡️ Scenario 3: Enforcing Strict Egress Perimeter & Data Exfiltration Prevention
- **The Problem:** Default Azure virtual network subnets allow unrestricted direct outbound connectivity to the internet, creating risks of unauthorized data egress or malware command-and-control communication.
- **The Solution Implemented:**
  1. Designed and deployed an **Enterprise Hub-and-Spoke topology** governed by User-Defined Routes (UDRs) with `0.0.0.0/0` pointing directly to the private IP of **Azure Firewall Premium**.
  2. Implemented TLS inspection, IDPS (Intrusion Detection and Prevention System), and structured Application Rule Collections restricting egress to explicitly approved domain FQDNs.
  3. Converted all cloud PaaS service access (Azure Key Vault, Storage Accounts, databases) to communicate solely via **Azure Private Endpoints**, completely removing public internet exposure.

### 💰 Scenario 4: Shift-Left DevSecOps & FinOps in Continuous Integration
- **The Problem:** Architectural anti-patterns (such as unencrypted disks, publicly accessible storage, or over-provisioned expensive VM instances) were often discovered only after infrastructure was already provisioned and billed.
- **The Solution Implemented:**
  1. Integrated **Checkov & tfsec** into PR validation workflows to enforce CIS Azure Foundations Benchmark rules before code merges.
  2. Added **Infracost** directly to pull requests, posting automated markdown tables showing the exact monthly financial delta (`+$34.20/month`) and flagging budget threshold breaches.
  3. Configured branch protection rules requiring passing security and cost checks alongside 2 senior engineer peer approvals.

## 🛡️ Production Resilience, SRE & Disaster Recovery

```
                            [ Resilient Cloud SLA Framework ]
                                           │
         ┌─────────────────────────────────┼─────────────────────────────────┐
         │                                 │                                 │
 [ High Availability ]            [ Disaster Recovery ]            [ Observability & Telemetry ]
  • Multi-AZ Nodepools (1, 2, 3)   • RTO < 15 Min (ASR Runbooks)    • Log Analytics KQL Queries
  • Zone-Redundant PaaS Instances  • RPO < 5 Min (Geo-Replication)  • Azure Monitor Dynamic Alerts
  • Self-Healing VMSS Probes       • Immutable GRS Storage Vaults   • Distributed APM Tracing
```

- **Storage Durability:** Zone-Redundant Storage (ZRS) across three physical availability zones for operational data; Geo-Redundant Storage (GRS) for critical backups and long-term compliance archives.
- **Disaster Recovery Targets:**
  - **RTO (Recovery Time Objective):** `< 15 minutes` via scripted failover automation and infrastructure recovery runbooks.
  - **RPO (Recovery Point Objective):** `< 5 minutes` through continuous transactional database replication.
